# 팔괘 공용 자료 밑바탕 — `data/trigrams/` (261124_1930 LAUDE)

JJDD·SHANA 요청: 64괘처럼 팔괘도 고유 번호 폴더를 두고, 아이콘을 그곳에 모은다. 이번 작업은 밑바탕까지다. 그림과 화면 배치는 JJDD·SHANA가 협의해 진행한다.

## 고유 번호

- 3자리 문자열이다. 왼쪽부터 **위 효·가운데 효·아래 효**이고, 양 = 1, 음 = 0이다. 선행 0을 지킨다(`"001"`).
- 숫자 `value`(0~7)는 이 문자열을 이진수로 읽은 값이다. `data/hexagrams.json`의 `trigrams.*.value`와 같다.
- 기존 `lines` 배열은 **아래 효부터**다. 문자열과 방향이 반대다.
- **64괘 고유 번호 = 상괘 3자리 + 하괘 3자리**다. 예: 지풍승 `000110` = 곤 `000` + 손 `110`.

|---|---|---|---|---|

| 100 | 4 | gen | 간 艮 ☶ | 산 |

### 정보 파일(`{code}/…_trigram_Laude.json`)

- 항목
  - `code`, `value`, `id`
  - `nameKo`, `name`, `symbol`, `natureKo`, `nature`
  - `lines`와 방향 설명 `lineOrder`
  - `imageFolder`
- **기준 데이터**는 `data/hexagrams.json`의 `trigrams`다. 같은 값이 두 곳에 있으므로 검사가 둘이 같은지 확인한다.
- `icon`(아이콘 등록 자리): 지금은 `status: "unregistered"`이고 `current`·`intent`·`alt`는 `null`, `versions`는 `[]`다. 없는 그림 경로나 완성된 것 같은 설명은 넣지 않았다.
- `iconIdea`: JJDD 문서 `docs/eight-trigram-icons.md`의 '05. 여덟 가지 자연의 첫 후보' 표를 옮겼다(구상일 뿐, 그림 없음).

### 목록 파일(`…_trigram-index_Laude.json`)

- `codeRule`: 번호 규칙과 64괘 연결 규칙
- `trigrams`: 여덟 괘의 `code`·`value`·`id`·정보 파일·이미지 폴더
- `orders`: 일렬 순서. 폴더와 번호는 고정하고, 보여 주는 순서만 여기서 고른다.
  - `binary`: 이진 번호순 0~7. 규칙으로 정해지므로 `verified: true`다.
  - `screen`: 지금 [팔괘 성격 보기]의 순서(건·태·리·진·손·감·간·곤)다. 공용 모듈 `TRIGRAM_ORDER`와 같은지 검사한다. 화면은 아직 이 목록 파일을 읽지 않는다.
  - `xiantianNumber`: 선천 팔괘의 수(乾一 兌二 離三 震四 巽五 坎六 艮七 坤八). **`verified: false`**
- `arrangements`: 방위 배치
  - `xiantian`(선천): 乾 남 · 坤 북 · 離 동 · 坎 서 · 震 북동 · 兌 남동 · 巽 남서 · 艮 북서. **`verified: false`**
  - `houtian`(후천): 震 동 · 巽 남동 · 離 남 · 坤 남서 · 兌 서 · 乾 북서 · 坎 북 · 艮 북동. **`verified: false`**
- `notes`
  - '후천 순서'처럼 한 줄로 늘어놓는 순서는 시작 방위와 도는 방향이 있어야 정해진다. 그래서 지금은 일렬 순서를 넣지 않았다.
  - 낙서 1~9 방위수는 고유 번호로 쓰지 않는다.

### 출처에 대해

- 선천 수와 두 방위 배치는 LAUDE가 기억으로 적은 것이다. 2026-11-24 이 작업 환경에서는 위키백과 등 외부 문헌에 접속하지 못해(프록시 차단) 문헌과 대조하지 못했다. 그래서 `verified: false`로 두었다.
- 화면에서 쓰기 전에 문헌(예: 「설괘전」, 주희 『주역본의』 권두 그림, 위키백과 Bagua)과 대조한다. 그다음 출처를 적고 `verified: true`로 바꾼다.
- 대조 전에는 어떤 화면도 이 배열을 쓰지 않는다.

## 이미지 보관 원칙

- 팔괘 아이콘은 `data/trigrams/{3자리}/images/`, 64괘 그림은 `data/hexagrams/{6자리}/images/`에 둔다.
- 팔괘 아이콘은 **정사각형 규격을 검토 중**이다. 크기·색·그림체는 아직 정하지 않았다. 64괘 그림의 2:1 규격을 팔괘에 그대로 적용하지 않는다.
- 그림 안에 글씨나 괘 기호를 넣지 않는다. 이름·설명·괘 기호는 화면에서 따로 보여 준다(다른 언어로 바꾸기 쉽게).
- 이번 작업에서는 이미지를 만들거나 옮기지 않았다. 풍지관 이미지(`assets/images/wind-earth.webp`)와 홈 참조는 그대로다.

## 아이콘 등록(다음 작업 때)

1. 파일을 `data/trigrams/{code}/images/`에 날짜·작성자가 붙은 이름으로 넣는다. 예: `data/trigrams/110/images/261125_1000_xun-icon_Shana.png`
   - 고친 그림은 새 이름으로 더하고, 이전 파일은 지우지 않는다.
2. 같은 폴더의 정보 파일(`{code}/…_trigram_Laude.json`)을 새 날짜 판으로 만들어 `icon`을 채운다.
   - `status`: `"registered"`
   - `current`: 쓸 파일 경로(예: `data/trigrams/110/images/261125_1000_xun-icon_Shana.png`)
   - `versions`: `[{ "path": …, "createdAt": …, "author": …, "note": … }]`. 이전 그림도 남긴다.
   - `intent`: 그림 의도(예: "휘어지며 이어지는 선으로 보이지 않는 바람의 흐름")
   - `alt`: 대체 설명(화면 낭독용)
3. 목록 파일의 `trigrams[].info`를 새 정보 파일로 바꾼다.
4. `node tests/261124_1930_trigram-data_Laude.mjs`를 돌린다.
   - 등록 상태에서는 파일이 실제로 있는지, 버전 목록에 있는지, 의도·대체 설명이 있는지 검사한다.
5. 화면에 붙이는 일([팔괘 성격 보기] 항목 오른쪽 작은 아이콘 등)은 따로 협의해 진행한다.

## 검사

`node tests/261124_1930_trigram-data_Laude.mjs`

- 여덟 팔괘의 번호·value·식별자·효 배열·이름이 기준 데이터와 같은지, 고유 번호 유일·선행 0

- 모든 순서·배치에 여덟 괘가 중복·누락 없이 있는지
- 화면 순서가 공용 모듈 `TRIGRAM_ORDER`와 같은지
- 화면 코드가 아직 목록 파일을 읽지 않는지

# 아이역 공통 언어 기반 — 한국어 검토 문서

## 이번에 만든 것

최상위 홈의 ‘언어 선택’에서 한국어 또는 English(번역 준비 중)를 고른다. 선택은 `iyeok.language.v1` 키로 이 브라우저의 localStorage에만 저장한다. 같은 출처의 홈·동전점·시초점 메뉴·배우기·옵션 화면이 함께 사용하며, 다른 탭에도 storage 이벤트로 반영한다. 언어를 바꾸기 위해 페이지를 새로고침하거나 점·배우기 상태를 초기화하지 않는다.

이번에는 영어 번역을 작성하지 않았다. 영어 파일의 `null`은 번역 대기 자리이며 사용자 화면에 null·빈칸·메시지 키를 표시하지 않는다. 준비된 번역이 있으면 그 항목부터 적용하고, 없으면 한국어 원문을 유지한다. 영어가 준비 중인 동안 문서의 기본 `lang`은 실제 주 언어인 한국어다. ‘번역 준비 중’ 안내와 홈으로 가는 언어 설정 링크를 하위 화면에 표시한다.

선택값은 같은 브라우저·같은 도메인에서 공유된다. 다른 기기·다른 브라우저로 동기화하지 않는다. 저장소가 차단되면 현재 화면의 선택으로 동작하며 저장할 수 없다고 안내한다. 사용자 진행 기록이나 질문을 언어 설정에 저장하지 않는다.

## 공통 파일

`assets/i18n/` 아래 이번 버전 파일:

- `261121_1715_language_Shana.js`: 언어 읽기·저장, 번역 불러오기, 안전한 텍스트 적용, 동적 화면과 다른 탭 동기화. `window.iyeokLanguage`와 모듈 API를 제공한다.
- `261121_1715_language_Shana.css`: 언어 설정 영역만 꾸민다. 공통 스타일을 변경하지 않는다.
- `261121_1715_locales_Shana.json`: 언어 코드·표시 이름·상태·파일 목록.
- `261121_1715_ko_Shana.json`: 한국어 기준 문구와 출처 경로, 숫자 안내문 템플릿.
- `261121_1715_en_Shana.json`: 영어 번역 대기 자리. 이번 공개 버전의 번역 값은 모두 null이다.

현재 카탈로그는 활성 페이지·연결된 JS 모듈의 고정 문자열·64괘 한국어 콘텐츠·괘 이름을 기준으로 뽑은 888개 원문 후보와 숫자 안내문 템플릿 3개다. 이 숫자가 모든 동적 문장·모든 조합을 번역 완료했다는 뜻은 아니다. 사용하지 않는 문자열 후보나 기술 식별자가 섞일 수 있으므로 `origins`의 실제 화면 맥락을 보고 한글을 확정한 뒤 번역한다.

## 로드·샤나가 번역을 채우는 순서

1. 한국어 문구와 맥락을 JJDD와 확정한다. 번역 작업을 이유로 한글 원문을 임의로 고치지 않는다.
2. 한국어·영어 카탈로그를 새 날짜·편집자 버전으로 복사한다. 이번 판의 `source`를 보고 같은 키에 번역을 넣는다. 번역 전인 값은 null로 유지한다.
3. 한문 원문과 한국어 독음을 영어 번역문으로 덮어쓰지 않는다. 한국어 독음을 영문 독음으로 제공할지는 별도 편집 결정이다.
4. `locales` 파일을 새 버전으로 만들고 새 카탈로그 경로를 연결한다. 공통 모듈이 읽는 목록 참조와 HTML의 모듈 참조를 필요한 만큼 새 버전으로 갱신한다. 고정 HTML·서비스 워커 변경 전 원본을 날짜 백업으로 보존한다.
5. 그 언어가 아직 일부만 번역되었으면 status는 `preparing`을 유지한다. 전체 주요 경로·동적 장면·접근성 문구를 검토한 뒤에만 `ready`로 바꾼다. 번역 몇 줄을 채웠다는 이유로 전체 번역 완료로 표시하지 않는다.
6. 동전점의 공통 언어 파일도 오프라인 목록에 포함하고 캐시를 갱신한다. 이번에는 v70→v71, 기존 캐시 갱신·실패·재시도 로직은 그대로다. 시초점에 새 서비스 워커를 만들지 않는다.

새 언어는 언어 목록에 코드·자국어 이름·새 파일을 더하면 된다. 우선 ko/en으로 검토하며 일본어·중국어 등의 추가는 후속 작업이다. 영어를 자동 번역하거나 외부 번역 서비스로 전송하지 않는다.

## 고정 글과 동적 글 처리

기존 고정/동적 화면을 전부 다시 작성하지 않고도 적용할 수 있도록, 텍스트 노드와 접근성 속성(aria-label, aria-valuetext, alt, title, placeholder)을 원문 키로 대조한다. 버튼·입력·DOM 요소 자체나 innerHTML을 번역문으로 교체하지 않으므로 이벤트와 진행 상태를 유지한다. 동적 화면이 새로 만든 글은 MutationObserver로 대조한다. 앱이 원래 글을 새로 썼을 때는 이전에 번역해서 쓴 글과 구분해 원문을 갱신한다.

- 공백을 정규화한 원문에서 안정적인 `text.해시` 키를 만든다. 추출 도구는 키 충돌을 검사한다. 한글 원문이 바뀌면 새 키로 보고 재검토하며 이전 번역을 잘못 적용하지 않는다.
- 원문 한자 영역 `.is-original`, `lang=zh-Hant/lzh`, 코드·스크립트·스타일 및 `data-no-i18n` 영역은 자동 변환 대상에서 제외한다.
- 번역문은 HTML이 아닌 텍스트로만 넣는다. `<b>` 같은 내용도 태그로 실행하지 않는다.
- 숫자가 바뀌는 문장을 숫자별로 끝없이 등록하지 않는다. `{left}` 등의 매개변수를 가진 명시적 `templates`나 `t(key, params, fallback)`를 사용한다.
- 예: `runtime.split`의 한국어 틀은 `왼쪽 {left} · 오른쪽 {right} · 합계 {total}`다. 번역문에서도 같은 매개변수 이름을 보존한다.
- 아직 등록되지 않은 동적 장면·중첩 조합 문장은 한국어로 남는다. 실제 영어 채우기 단계에서 해당 문장을 키 또는 템플릿으로 추출·등록하고, 첫 장면뿐 아니라 여섯 효·완료·오류·옵션까지 확인해야 한다. 이 작업은 번역을 채워 가는 과정에 포함된다.

명시적 API:

```javascript
await window.iyeokLanguage.ready;
await window.iyeokLanguage.setLanguage('en');
const code = window.iyeokLanguage.getLanguage();
// 새 기능에서는 한글 fallback과 확정된 키를 직접 사용해도 된다.
const label = window.iyeokLanguage.t('runtime.split', { left: 24, right: 25, total: 49 });
```

원문 후보 추출 도구 `scripts/261121_1715_extract-language_Shana.py`는 실행 시 `--output`으로 지정한 **새 파일만** 생성한다. 기존 파일을 덮어쓰지 않으며 활성 경로를 따라 읽는다. 자동 추출은 번역의 맥락 검토나 동적 템플릿 설계를 대신하지 않는다.

## 사용자에게 보이는 한계

번역이 아직 없어 English를 선택해도 본문은 한국어다. 선택 저장·공유와 준비 안내가 먼저 제공되는 단계다. 나중에 검토한 영어 문구를 채우면 해당 글이 바뀐다. 한문 원문은 유지한다. PWA 설치 이름·아이콘 이름처럼 설치할 때 고정되는 운영체제 표시와 과거 docs 문서·백업 파일까지 언어 선택으로 바꾸는 기능은 이번 범위가 아니다.

## 검증과 보존

브라우저 검증 파일: `tests/261121_1715_language.browser_Shana.cjs`. 실제 공개 번역 파일을 바꾸지 않고 시험용 번역 응답으로 문구·동적 숫자·한국어 복원·HTML 비실행을 확인한다. 공통 언어 선택, 화면 이동·다른 탭 동기화, 진행 상태 유지, 저장소 차단·번역 파일 실패 때의 한국어 유지, 모바일/PC 가로 넘침, 동전점 결과와 오프라인, 배우기 첫 효 경로를 검증한다. 기본 테스트 9개와 서비스 워커 문법·목록도 확인한다. 실제 iPhone Safari·VoiceOver는 별도 기기 검토 대상이다.

원본 백업은 `backups/i18n/261121_1715_원래경로.html` 등으로 보존했다(경로 구분자는 -로 표현). 한글 괘사·계산·배우기 진행 코드·공통 스타일·기존 옵션 저장값은 수정하지 않았다. 변경된 고정 파일은 다섯 진입 HTML과 서비스 워커뿐이다.

이 문서는 한글 검토판이다. 영문 설명·합본은 JJDD와 협의한 뒤 만든다.
